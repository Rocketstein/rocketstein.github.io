About

Mathematics in the foundation.
Game systems in practice.

I’m a C++ game and rendering programmer interested in the point where low-level systems become useful creative tools and responsive gameplay.

My work spans custom engine architecture, real-time rendering, editor tooling, physics, procedural systems, and complete playable game flows.

Background

A systems-minded route into games.

I graduated from the University of Illinois Urbana-Champaign with a degree in Mathematics and Computer Science. That combination shaped how I approach game technology: start from the underlying model, make the trade-offs explicit, then turn the result into something that can be tested visually and interactively.

After graduation, I completed Krafton Jungle’s intensive Game Tech Lab programme. In rotating small teams, I helped develop a C++ and DirectX 11 engine from its early foundations through rendering, editor, reflection, animation, particle, physics, scripting, and gameplay milestones.

I also co-developed Volumetric Super Storm, an Unreal Engine plugin published on Fab. The project reinforced a different side of engine work: building artist-facing controls, editor workflows, reusable assets, and rendering features that make technical systems approachable to other disciplines.

I am currently studying entity-component-system architecture through an independent engine project, with particular attention to data ownership, system boundaries, iteration performance, and tooling.

How I work

Build, observe, refine.

Make ownership visible

I prefer APIs and data paths that make lifetime, responsibility, and mutation clear rather than relying on hidden global behaviour.

Debug the system, not the symptom

I narrow reproduction conditions, inspect data flow, and verify assumptions before treating a visible failure as a local bug.

Ship the feature in context

A renderer, editor tool, or gameplay component matters most when it is integrated, usable, and demonstrable in the final experience.
